1. Summary

Large language models are strong at reasoning but have two practical limits: they forget everything between sessions, and they cannot watch video. This work addresses both with plain files and local tools rather than paid infrastructure.

2. System 1: the context harness

2.1 The ontology graph

Knowledge is stored as many short Markdown notes in Obsidian. Each note declares its parent in its front matter (up: "[[INDEX]]") and links related notes in the text ([[Note]]). Parent links form a tree from one index; cross links form the rest of the graph. A central Harness branch holds the rules that apply to every project; each project holds a short STATE note and an append-only run-log. Some vaults are generated by code: ontology.py defines domains and concepts, and build_vault.py writes one linked note per concept and attaches real audience questions to it.

2.2 Context management: a fixed, short reading path

A new session never re-reads an old chat. It reads five things in order and then starts work. Lessons are opened only when something fails. Bulk data follows the same rule: local tools turn it into compact files first, and the assistant reads only those (Section 3).

2.3 Relearning: mistakes become rules

Every failure or correction is written as one row: symptom, cause, fix. When the same lesson appears a second time it is promoted: into a script that makes the mistake impossible, a line in the done-checklist, or a standing rule. The checklist runs before any task is called done.

New kinds of work run first with the strongest model and the user, and the exact protocol (every measurement, its script, thresholds, what an agent may and may not read) is written during those rounds. Cheaper models then run the job from the protocol alone. A model log records which model did best on which task type.

Example: a local vision tagger was right on only 40% of 50 hand-checked shots. The lesson (test on a gold set covering every label, define each label in the prompt) raised it to 76% and became a checklist rule.

3. System 2: the video understanding pipeline

A video is treated as audio and frames on one clock. Local tools split them, measure each, and merge the results by timestamp. The language model never watches the video; it reads a one-page summary, the transcript and a few contact sheets.

3.2 Measured token saving

3.3 From a long stream to short clips

  1. Find moments. Windows of 25–62 seconds that start on a new sentence and end on a finished one are scored on loudness bursts, sustained loudness, reaction words, an opening hook, a payoff at the end, speech density, the YouTube "most replayed" heatmap, and penalties for dead air and filler. Picks are spread at least three minutes apart; static menus are pushed down by an on-screen motion check.
  2. Judge. Claude Haiku scores the best 25 in one call. If the nightly budget is spent, a local Qwen3 4B model judges instead.
  3. Cut. FFmpeg builds 1080×1920 clips (facecam on top, gameplay below, or a blurred background), burns in word-timed captions, and normalises loudness.
  4. Write and check. Claude Sonnet writes a label, three hooks, a title and a caption using what the team's study of 1,000+ clips found. Every text passes rule checks (length, blocked topics, quotes that must appear in the clip) and a local-model voice check.
  5. Human review. Nothing is posted automatically; every clip waits for approval in a review note.

3.4 Responsible collection

The downloaders behave like one careful person: the user's own logged-in session (cookies exported from their browser, never a typed password), a home connection rather than a server, at least 30 s between Instagram downloads, a 10-minute pause on any rate-limit warning, and a full stop with a STOP file on a login challenge or block. Comments are stored as text and like counts only, without usernames, and local videos are deleted after analysis. Certificate problems are fixed with the operating system's certificate store, never by turning checks off.

4. Engineering choices

Two GPU stages (cpu, then gpu)A 6 GB GPU fits one heavy model at a time: Whisper, then Demucs, then the vision model.
Resume-safe scriptsEvery bulk job appends results and skips finished items, so a crash or reboot loses nothing.
Resource gatesHeavy steps wait for free RAM, VRAM and disk; a daily cap limits Claude calls.
Local first, Claude lastFree local models do the volume; the paid model does judgement and writing.
Status wordsEvery result is labelled measured (a script over all the data), read (a person or model looked), or guess.

5. Limitations

  • The 37% overall token figure, the 300–400 s comprehension time and the 20+ delegates are the team's own estimates, not a controlled study.
  • Camera-motion thresholds are not yet validated against hand labels; the vision tagger reached 76% on a 50-shot gold set.
  • The language model reads transcripts and measured audio; it does not hear tone of voice.
  • Scripts carry the authors' machine paths and need editing to run elsewhere.
